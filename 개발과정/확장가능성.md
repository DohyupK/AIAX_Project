# 확장가능성 (문서만 · 당장 기능 개발 없음)

이 문서는 **나중에 열 수 있는 자리**만 적습니다.  
여기에 적혀 있다고 해서 **지금 구현하라는 뜻이 아닙니다.**  
실제 기능·라이브러리·DB를 만들 때는 반드시:

1. 사용자가 구현 대상을 **명시**하고  
2. 【구현 전에 확인 부탁드립니다】로 재확인하며  
3. 라이브러리는 **설치될 패키지를 전부 명시**해 승인받은 뒤에만 진행합니다.

관련 규칙: [AGENTS.md](../AGENTS.md) 「에이전트 단정 금지」.

---

## 1. ML / DL

- **원문:** 머신러닝·딥러닝을 나중에 합칠 수 있게 구상.
- **지금:** 모델·학습·추론 API·벡터DB 등 **구현하지 않음.**
- **나중에 열 때:** 서빙과 학습 분리, 웹 요청 스레드에서 무거운 학습 금지 등을 별도 설계·승인.

## 2. PostgreSQL 이관

- **원문:** 이후 Linux/서버·PostgreSQL. 지금은 목업.
- **지금:** 개인 폴더 `data/` SQLite 수준·`DB연동_내역` 기록 체계만.
- **나중에 열 때:** 소문자 snake_case, 커넥션 수명, 대소문자·API 연동 검토. 스키마·ORM·라이브러리는 항목 승인 후.

## 3. 로그인 / RBAC

- **확정:** 지금 만들지 않음. 확장 자리만.
- **지금:** 인증 UI·세션·역할 코드 **없음.**
- **나중에 열 때:** 별도 의도 확인 + 보안(해시 등)은 6항으로 제시·승인.

## 4. 제품 방향 후보 — 품질 불량 추적 + RAG

- **초기에 말한 것:** 제조 AX 방향으로서 품질 불량 추적과 원인 가이드용 RAG 문서 탐색 **가능성**.
- **지금:** 해당 화면·API·목업 스키마·RAG 파이프라인 **구현하지 않음.**  
  (에이전트가 “다음 기능”으로 단정하지 말 것.)
- **나중에 열 때:** 사용자가 기능명을 지정한 뒤 의도 확인·라이브러리 승인·DH 등 담당 폴더에서만 개발.

## 5. page_registry ↔ 개인 폴더 실연동

- **지금:** 루트 [`page_registry.md`](../page_registry.md)와 사이드바 **카테고리 자리(JH~DH)** 만.
- **나중에 열 때:** 등록표의 상대경로로 개인 `main`/페이지를 실제로 조립. 등록 시 승인 문구 유지.

## 6. FastAPI / Pandas 등 백엔드 스택

- **원문 방향:** Python(FastAPI, Pandas 등), Next.js(루트 셸은 도입됨).
- **지금:** FastAPI·Pandas **미설치·미구현.** Next 루트 셸만 승인·도입됨.
- **나중에 열 때:** uv로 패키지 추가, 설치 목록 전부 명시 후 승인.
