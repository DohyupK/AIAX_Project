# 전달사항 — 모델 레지스트리 테이블·API 요청 (DH → MS)

- 작성: DH, 2026-11-17
- 대상: DB 스키마 담당 MS
- 화면: JH Model Management (`/model-management`)
- 모델 아티팩트: TM `TM/model/DieCasting_*`
- 상태: **요청 (테이블·API 준비되면 JH가 `data.ts` 목업을 교체)**

## 배경

JH Model Management는 공정별 ML/DL 모델 목록·성과지표·배포 여부를 보여 줍니다.  
지금은 DB가 없어 **`JH/frontend/pages/model_management/data.ts` 목업**으로 TM DieCasting 모델 56건을 넣고 있습니다.

이후 **모델 레지스트리 테이블**이 생기면 화면은 API 목록으로 바꾸고, 등록·배포 여부도 DB에 저장할 예정입니다.  
스키마 이름·타입은 MS 명명규칙에 맞춰 조정해 주세요.

## 요청 1 — 테이블 (예: `mart.model_registry` 또는 동등)

| 컬럼(예시) | 타입(예) | 설명 |
|------------|----------|------|
| model_id | bigserial / uuid | PK |
| name | text | 모델명. 규칙 `DieCasting_{Algo}_{YYYYMMDD}_{NN}` |
| algo | text | XGB / LGBM / CatB / HGB / GB / RF 등 |
| version | text | 예: v1.0, exp |
| process_code | text | CAST-OPT / CAST-QC / SAFE-GATE |
| created_at | date 또는 timestamptz | 학습·등록일 |
| deployed | boolean | 현재 대시보드 배포 여부 (공정당 1개 권장) |
| file_path | text | 예: `TM/model/DieCasting_XGB_20261114_09/DieCasting_XGB_20261114_09.pkl` |
| file_name | text | 파일명 |
| accuracy | numeric | 0~1 |
| recall | numeric | 0~1 |
| precision | numeric | 0~1 |
| f1 | numeric | 0~1 |
| description | text | 설명 |
| apply_count | int | 배포 적용 횟수(선택) |

- 동일 `name` 중복 금지 또는 `(name, version)` 유니크.
- `deployed=true`는 공정(`process_code`)당 최대 1행이 되도록 제약 또는 앱 규칙.

## 요청 2 — API (담당 확정 후)

| 메서드 | 경로(예) | 용도 |
|--------|----------|------|
| GET | `/api/models?process=` | 목록·필터 |
| GET | `/api/models/{id}` | 단건 |
| POST | `/api/models` | 등록 (메타 + 선택적 파일 경로) |
| PATCH | `/api/models/{id}` | 메타·지표 수정 |
| POST | `/api/models/{id}/deploy` | 배포 전환 (기존 배포 해제) |

파일 바이너리 저장소는 이번 요청 범위에서 제외해도 됩니다. 메타·경로만 먼저 있어도 JH 목록 연동은 가능합니다.

## JH가 바꿀 부분 (참고)

- `JH/frontend/pages/model_management/data.ts` → API 호출
- 등록 폼은 이미 `DieCasting_{Algo}_{날짜}_01` 형태로 이름을 만듦 (순번은 서버 채번 권장)

## 요청

MS는 위 테이블·(가능하면) API 초안을 잡아 주시고, 준비되면 DH/JH에 알려 주세요.  
TM 폴더·모델 파일 내용은 이번 요청에서 수정하지 않습니다.
