## 현재 상태 (2026-11-18 조회)

| 항목 | 상태 |
|------|------|
| `ai.model_registry`, `ai.model_metric_cast_qc1`·`_cast_qc2`·`_safe_ppe` | 화면 연결 완료(읽기, 계정 `app_lake`). **모두 0행** → 화면 「등록된 모델 없음」 |

## 요청

1. **앱 전용 쓰기 계정 (예: `app_ai`)** — 인사의 `app_hr` 과 같은 방식으로 필요한 테이블만:
   - `ai.model_registry`, `ai.model_metric_cast_qc1`·`_cast_qc2`·`_safe_ppe`: INSERT·UPDATE(등록·배포 전환), 필요하면 DELETE
   - **(2026-11-19 추가)** `ai.model_robustness`: INSERT·DELETE — 아래 「추가 요청」 참고
   - **(2026-11-19 추가)** `ai.quality_prediction`: INSERT·UPDATE — 아래 「추가 요청 2」 참고
   - `ai.defect_label`, `ai.defect_discard`: INSERT·DELETE (불량 유형 라벨링 「완료」 저장 — 같은 이유로 막혀 있음)
   - 비밀번호는 루트 `.env` 로 전달 (Git 밖). 서버 `.env` 반영은 DH
2. **화면 「+」로 등록할 예정** — 위 계정이 생기면 JH 가 저장 API(`POST /api/models`: registry + 지표 한 트랜잭션)를 붙이고 버튼 막힘을 해제함. 등록은 `org.model_management_page` edit 권한자(TM 등)가 화면에서.
3. **(선택) 그 전에 모델이 필요하면** — MS(또는 DH)가 관리자 계정 `shift` 로 직접 등록 (관리 작업). 등록할 모델·공정·지표 값은 TM 확인. 참고: 품질 검사 1차에 쓰는 `DieCasting_XGB_20261114_09` 는 `CAST-QC1`(= 품질 1차 검사)로 등록.

## 추가 요청 — `ai.model_robustness` 쓰기 권한 (2026-11-19)

11-19 서버에 새로 생긴 `ai.model_robustness`(모델 강건성, 조건별 성능)도 위 쓰기 계정 권한에 넣어 주세요. 처음 요청(11-18) 때는 없던 테이블이라 목록에 빠져 있었음.

| 권한 | 이유 |
|------|------|
| INSERT | 품질 2차 모델 등록 시 TM 평가 결과 **CSV**(`condition,accuracy,recall,precision,f1`)를 첨부하면 조건별 행 저장 |
| DELETE | 「결과 다시 올리기」 = 그 모델의 강건성 행 전체를 지우고 새 CSV 로 교체 |

- 저장은 **registry + `model_metric_cast_qc2` + `model_robustness` 한 트랜잭션** 예정 → 이 테이블 권한이 빠지면 품질 2차 모델 등록 전체가 실패(롤백)함.
- PostgreSQL 권한은 테이블 단위라 같은 `ai` 스키마여도 따로 GRANT 필요 (스키마 전체·`DEFAULT PRIVILEGES` 로 줄 경우는 MS 판단).
- 현재 상태: 0행, 화면은 읽기만 연결 완료 (Model Management 품질 2차 「강건성」 팝업, `GET /api/models/{idx}/robustness`, 계정 `app_lake`).
- 리포 `MS/db/init/11_ai.sql` 에 `model_robustness`(및 `quality_image_pool`·`llm_feedback`, `mes.investment_casting_image` 삭제)가 아직 없음 — 서버와 맞춰 주세요.

## 추가 요청 2 — `ai.quality_prediction` 쓰기 권한 (2026-11-19)

품질 검사 화면에 2차(DL) 검사를 연결함 (`GET /api/casting/second`, 이미지 `mes.casting_image` → TM `DieCasting_CNXV2T_20261117_01.onnx`). 지금은 결과를 서버 메모리에만 두고 있어 서버를 다시 켜면 다시 추론함.

| 권한 | 이유 |
|------|------|
| INSERT | 샷별 2차 판정 저장 (`casting_id`, `model_name`, `version`, `result` 'pass'/'fail', `confidence_score`, `predicted_at`) |
| UPDATE | 같은 샷을 새 배포 모델·바뀐 이미지로 다시 판정할 때 덮어쓰기 (PK = `casting_id`) |

- 외래키 `(model_name, version) → ai.model_registry` 때문에, 쓴 모델이 레지스트리에 등록돼 있어야 저장 가능. 지금 쓰는 기본 모델 `DieCasting_CNXV2T_20261117_01` 은 미등록 → 등록 필요(CAST-QC2, 지표는 TM 문서 `TM/model_dl/DieCasting_CNXV2T_20261117_01/DieCasting_CNXV2T_20261117_01_METRICS.md`: accuracy·recall·precision·f1 모두 1.0000).
- 기록: [DB연동_내역/2026-11-19_JH_quality_second_dl.md](../../DB연동_내역/2026-11-19_JH_quality_second_dl.md)

## 추가 확인 (2026-11-19)

1. **`ai.model_robustness` 지표** — 공정과 무관하게 `accuracy_score` 고정. 품질 1차(CAST-QC1)는 성과지표가 PR-AUC·Recall·Precision·F1 이라, 1차 모델의 강건성도 accuracy 로 저장하게 됨. 의도한 구조인지 (2차 전용이면 그대로 OK)
2. **`ai.llm_feedback` 용도** — 어느 화면에서 무엇(`target_type`·`target_ref` 값)을 보여 줄지. 정해지면 JH 화면 연결 검토
3. 강건성 조건 표시 순서 — 지금은 화면 코드에 고정(TM 평가 14개 순서). 조건이 자주 바뀔 예정이면 순서 칼럼 검토

쓰기 계정이 생기기 전이라 위 요청 3번 방식(관리자 직접 등록)으로 부탁드립니다. MS 또는 DH 가 관리자 계정으로 실행.

- 파일: [sql/2026-11-19_qc2_model_register.sql](sql/2026-11-19_qc2_model_register.sql) — 한 트랜잭션, 다시 실행해도 안전

## 참고 — 계정 현황 (2026-11-18 조회)

| 계정 | ai 모델·라벨 테이블 |
|------|---------------------|
| `shift` | 소유자·superuser → 모든 권한 |
| `app_lake` (JH API) | 읽기만 |
| `app_hr`·`app_mes`·`app_spark`·`app_mart` | 권한 없음 |

- JH API 는 `shift` 를 쓰지 않음 (앱이 관리자 권한으로 돌면 버그·유출 시 DB 전체 위험 — 최소 권한)
- **보안 확인 부탁**: 관리자 `shift` 비밀번호가 팀원 로컬 루트 `.env`(`POSTGRES_USER`/`POSTGRES_PASSWORD`)에 들어 있음. 관리자 계정 공유 범위는 DH·MS 판단

## 계정이 생기면 JH 가 할 일

- 등록·배포 API 추가 (배포 전환은 `deployed = true` 만 바꾸고 기존 배포 해제는 DB 트리거에 맡김)
- 화면 등록 폼 → API 저장, 버튼 막힘 해제
- 품질 2차 등록 폼에 강건성 CSV 첨부(검사·미리보기) → 등록 시 `model_robustness` 함께 저장
- 2차(DL) 판정 결과를 메모리 캐시 대신 `ai.quality_prediction` 에 저장·조회
