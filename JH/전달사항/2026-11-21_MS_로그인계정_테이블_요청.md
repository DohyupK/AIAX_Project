# 요청: 로그인 계정 테이블 `org.app_user` 추가 (JH → MS, DH 참조)

- 작성: JH / 2026-11-21
- 상태: 요청
- 배경: 로그인·회원가입 구현 완료. 계정은 지금 임시 SQLite(`JH/data/auth.db`)에 저장 → 정식 Postgres 테이블로 옮기려 함
  (기능 [`JH/기능표.md` 로그인·회원가입](../기능표.md#로그인회원가입-auth), 기록 [`DB연동_내역/2026-11-21_JH_auth_login.md`](../../DB연동_내역/2026-11-21_JH_auth_login.md))

## 1. 테이블 — init 새 파일 제안 `MS/db/init/31_로그인계정.sql`

```sql
-- 로그인 계정 (JH 로그인·회원가입). 아이디·비밀번호 = 본인 확인, 권한 = 사번(org 기존 규칙)
-- 관리자 계정은 여기 넣지 않음 (서버 .env ADMIN_ID / ADMIN_PASSWORD)
CREATE TABLE org.app_user (
    app_user_idx   bigint      GENERATED ALWAYS AS IDENTITY UNIQUE,
    user_id        text        PRIMARY KEY
                   CHECK (user_id ~ '^[a-z0-9][a-z0-9._-]{3,19}$'),          -- 소문자 4~20자 (앱과 같은 규칙)
    password_hash  text        NOT NULL CHECK (password_hash LIKE 'scrypt$%'),  -- 원문 저장 금지, scrypt 해시만
    employee_no    text        NOT NULL UNIQUE                                  -- 사번 1개당 계정 1개
                   REFERENCES org.employee(employee_no) ON DELETE CASCADE,      -- 사원 삭제 시 계정도 삭제
    email          text        NOT NULL CHECK (email LIKE '%_@_%._%'),
    created_at     timestamptz NOT NULL DEFAULT now(),
    last_login_at  timestamptz
);
COMMENT ON TABLE  org.app_user IS '로그인 계정. 이름·부서·직급은 org.employee / employee_info 원본을 조인 (중복 저장 안 함)';
COMMENT ON COLUMN org.app_user.password_hash IS 'scrypt$N$r$p$salt$hash — JH/api/auth/core.py hash_password';
COMMENT ON COLUMN org.app_user.last_login_at IS '마지막 로그인 성공 시각 (앱이 갱신)';

-- 권한: 기존 인사 API 계정 app_hr 재사용 (새 계정·비밀번호 없음)
GRANT SELECT, INSERT ON org.app_user TO app_hr;
GRANT UPDATE (last_login_at, password_hash, email) ON org.app_user TO app_hr;
-- ※ role_lake / role_spark 에는 주지 않음 — 비밀번호 해시가 lake·mart 로 복제되지 않게
```

## 2. 칼럼 결정 이유

| 칼럼 | 이유 |
|------|------|
| `user_id` PK + 형식 CHECK | 앱이 소문자로 바꿔 저장 → 대소문자 중복 불가. DB 에서도 같은 규칙으로 한 번 더 막음 |
| `password_hash` | 원문 금지. 형식 CHECK 로 실수로 원문이 들어가는 것 차단 |
| `employee_no` UNIQUE + FK | 권한의 기준. 실제 직원만, 사번당 1계정. 사원 삭제(인사 API 삭제 기능) 시 계정도 함께 삭제 |
| 이름 칼럼 **없음** | 이름은 `org.employee_info.employee_name` 이 원본 — 개명·수정이 바로 반영되게 조인 |
| `email` | 가입 때 받은 연락처 (인사 이메일과 다를 수 있음). 인사 이메일로 통일하려면 이 칼럼 없이 `employee_info.email` 사용 — **MS 판단** |
| `last_login_at` | 장기 미사용 계정 점검용 |
| `UPDATE (password_hash, email)` | 이후 「비밀번호 변경」 기능용 (지금은 미사용 — 빼도 됨) |

## 3. 앱 쪽 규칙 (참고 — DB 가 아닌 JH 코드에서 처리)

- 가입: 사번이 `org.employee` 에 있고 **`employment_status = 'active'`(재직)**, 이름이 `employee_info.employee_name` 과 같아야 함
- 로그인: 퇴사(`resigned`) 사번 계정은 로그인 거부
- 실패 잠금(5회/5분)은 앱 메모리 — 테이블 불필요

## 4. 같이 갱신 부탁 (MS 규칙: init 바꿀 때 같은 작업에서)

- `JH/api/auth/store.py` 함수 3개(`find_user`·`create_user`·`touch_login`)를 `org.app_user` + `HR_DATABASE_URL` 로 교체, 이름은 조인
