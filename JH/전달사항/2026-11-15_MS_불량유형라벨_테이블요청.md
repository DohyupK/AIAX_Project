# 전달사항 — 불량 유형 라벨링 테이블·API 요청 (JH → MS)

- 작성: JH, 2026-11-15
- 대상: DB 스키마 담당 MS (API는 담당자 확정 후 전달)
- 상태: **요청 (DB·API 준비되면 JH가 화면 저장 부분 교체)**

## 배경
JH가 「불량 유형 라벨링」 페이지(`/casting/defect-labeling`)를 만들었습니다.
2차(DL) 검사에서 불량 판정된 샷 이미지를 전문가가 보고 불량 유형을 라벨링합니다.
지금은 DB가 없어 **브라우저 저장(localStorage) 목업**으로만 저장합니다 — 같은 PC·브라우저에서만 유지, 공유 안 됨.

현행 `DB구조.md`(2026-11-10)에는 라벨·폐기 테이블이 없습니다. JH는 스키마를 바꾸지 않으므로 아래를 요청합니다.

## 요청 1 — 테이블 2개 (이름·스키마는 MS 명명규칙에 맞춰 조정)

### 라벨 테이블 (예: `mart.defect_label`)
| 컬럼 | 타입(예) | 설명 |
|------|----------|------|
| shot_id | bigint | 샷 번호 (production_count). `casting_id` FK로 바꿔도 됨 |
| line | text | 라인 (line_no1 ~ line_no3) |
| defect_types | text[] | 불량 유형 1개 이상: `BLOWHOLE` · `EDGE_BURR` · `SURFACE_ROUGH` |
| labeled_at | timestamptz | 라벨 시각 |

- (line, shot_id) 당 1행. 다시 라벨링하면 덮어씀.

### 폐기 테이블 (예: `mart.defect_discard`)
| 컬럼 | 타입(예) | 설명 |
|------|----------|------|
| shot_id | bigint | 샷 번호 |
| line | text | 라인 |
| reason | text | 현재 `UNDECIDABLE`(판정 불가)만 |
| discarded_at | timestamptz | 폐기 시각 |

- 규칙: 한 샷은 **라벨 테이블과 폐기 테이블 중 한 곳에만** 존재. `UNDECIDABLE`로 저장하면 라벨 행 삭제 + 폐기 행 추가, 다시 일반 유형으로 저장하면 그 반대.
- 학습(mart) 쪽에서 폐기 샷은 학습 데이터에서 제외하는 용도.

## 요청 2 — API (담당 확정 후)
| 메서드 | 경로(예) | 용도 |
|--------|----------|------|
| GET | `/api/casting/defect-labels?line=&date=` | 라벨·폐기 목록 조회 |
| PUT | `/api/casting/defect-labels/{line}/{shot_id}` | 저장 (body: `{ defect_types: [...] }`, UNDECIDABLE 포함 시 폐기 처리) |
| GET | `/api/casting/defect-images/{line}/{shot_id}` | 샷 촬영 이미지 (현재 목업 SVG) |
