## 서버에서 켜기 전에 결정할 것 (DH)

1. **서버에 Kafka·Flink 를 올릴지** — [`DB연동_내역/NCP_Postgres_수동설치.md`](../../DB연동_내역/NCP_Postgres_수동설치.md) 에 「Kafka / Spark / Flink 는 서버에 올리지 말 것 (로컬 처리)」 계획이 있음. 올린다면 서버 메모리 확인 (Kafka + jobmanager + taskmanager ≈ 2~3GB)
2. 로컬 처리 유지라면 → 아래 「B. 로컬 PC 에서 서버 DB 로」 사용

## A. 서버에서 실행

서버 Postgres 는 compose 가 아니라 `docker run` 단독 컨테이너(`aiax-postgres`) → job 은 `host.docker.internal` 로 호스트의 5432 에 접속 (compose 에 `extra_hosts` 추가해 둠).

```bash
cd <프로젝트>/MS/db
# ⚠ postgres 를 서비스 목록에 넣지 말 것 — compose 의 postgres(aiax-postgres-local)를 켜면
#   서버 DB(aiax-postgres)와 5432 포트가 겹쳐 실패하고, 켜지더라도 빈 DB 가 하나 더 생김
AIAX_DB_HOST=host.docker.internal docker compose up -d --build kafka flink-jobmanager flink-taskmanager

# 토픽 미리 생성 (lake_sync_consumer 는 토픽이 없으면 바로 종료되는 버그가 있음)
for t in aiax.image.ingest aiax.image.spark_sync; do
  docker exec aiax-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka:9092 \
    --create --if-not-exists --topic $t --partitions 3 --replication-factor 1
done

# job 제출 (한 번만 — 두 번 내면 같은 메시지를 두 job 이 처리)
docker exec aiax-flink-jobmanager /opt/flink/bin/flink run -d -py /opt/flink/jobs/image_ingest.py
docker exec aiax-flink-jobmanager /opt/flink/bin/flink list          # RUNNING 확인

# lake 복제 (DH 코드 그대로) — 서버 .env 의 DATABASE_URL(127.0.0.1)이 서버에선 맞음
cd <프로젝트>/DH/api && uv sync
uv run python -m image_pipeline.lake_sync_consumer                   # 상시 실행은 systemd 등록 권장
```

- 서버 루트 `.env` 에 `APP_MES_PASSWORD`, `APP_SPARK_PASSWORD` 필요 (Flink 컨테이너는 루트 `.env` 를 `env_file` 로 읽음)
- 관리 화면 8081: **ACG 에 열지 말 것** (job 취소까지 가능). 볼 때는 SSH 터널 `ssh -L 8081:127.0.0.1:8081 <서버>`

## B. 로컬 PC 에서 서버 DB 로 (지금 검증한 방식)

```bash
cd MS/db
AIAX_DB_HOST=gknushift.freemyip.com docker compose up -d --build kafka flink-jobmanager flink-taskmanager
# 토픽 생성·job 제출은 A 와 같음

# lake 복제 — 로컬 .env 의 DATABASE_URL 은 서버용(127.0.0.1)이라 호스트만 바꿔 실행 (.env 는 고치지 말 것)
cd DH/api
DATABASE_URL="$(grep -E '^DATABASE_URL=' ../../.env | cut -d= -f2- | sed 's#@127.0.0.1:#@gknushift.freemyip.com:#')" \
  uv run python -m image_pipeline.lake_sync_consumer
```

- 이 PC 공인 IP 가 NCP ACG 5432 허용 목록에 있어야 함

## 운영 메모

| 상황 | 방법 |
|------|------|
| job 멈추기 | `flink list` 로 JobID 확인 → `flink cancel <JobID>` (또는 8081 화면) |
| 코드 수정 후 재배포 | cancel → (Dockerfile 바뀌었으면 `--build`) → 다시 `flink run`. 처리 위치는 Kafka 커밋(그룹 `dh.image.flink_role_a`)에서 이어짐 |
| taskmanager 죽음 | 자동 복구 (약 1분 안 감지 후 재시작, 5초~2분 간격 재시도) |
| **jobmanager 재시작·컨테이너 재생성** | **job 이 사라짐 → 다시 `flink run` 필요** (HA 미구성). 처리 위치는 Kafka 커밋에서 이어지므로 유실 없음 |
| 로그 | `docker exec aiax-flink-taskmanager sh -c 'grep -h image_ingest /opt/flink/log/*.log'` — 시각이 **UTC** (KST −9h) |
| DB 오래 끊김 | job 이 계속 재시도하며 대기 (메시지는 Kafka 에 남음). DB 복구되면 자동 처리 |

## 남은 문제 (DH)

1. `lake_sync_consumer` (Python) 의 버그 2개는 그대로 — 토픽 없으면 종료, 실패 메시지 유실. Flink job 처럼 옮길지 결정 (지금은 Spark 실잡 `MS/db/spark/jobs/` 자리)
2. Kafka 메시지 1MB 한도 — 실제 카메라 이미지 크기 확인 후 MS 와 결정
3. 검증 목업 5건이 서버 mes·lake 에 남아 있음 (casting_id 는 [DB 기록](../../DB연동_내역/2026-11-19_JH_image_ingest_flink.md) 참고) — 삭제 여부 결정 대기
4. MS: 서버에 적용한 DDL 을 `MS/db/init/` 에 편입
