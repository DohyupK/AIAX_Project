## 증상

- `https://gknushift.freemyip.com/casting/defect-labeling` 에서 유형 고르고 「완료」→ `저장하지 못했습니다: Not Found` (또는 유사)
- 원인: 화면은 배포 서버 `/api` 를 치는데, JH API에 SQLite 저장 코드가 **pull·재시작 전**이면 옛 경로/응답

## 재현

1. 로그인 후 불량 유형 라벨링 → 미라벨 카드 → 유형 선택 → 「완료」

## 내 폴더 1차 점검

- 저장 API: `POST /api/casting/defects/{casting_id}/label` → `JH/data/defect_labels.db` (stdlib sqlite3)
- 목록: `GET /api/casting/defects` 가 SQLite 라벨 머지
- 프론트는 로그인과 같이 **같은 출처 `/api/...`** 호출 (nginx → :8000)
- 새 패키지 없음

## 요청 수정 범위 (DH — 서버만)

```bash
cd /root/AIAX_Project   # 실제 경로에 맞게
git pull
systemctl restart myapp
```

- `JH/data/` 쓰기 권한 확인 (없으면 `defect_labels.db` 생성 실패 → 503). `auth.db` 와 동일.
- `.env` / 패키지 추가 **없음**
- (선택) 개발 PC N 배지: 루트 `next.config.ts` 에 `devIndicators: false` 가 들어갔으면 Next도 재시작
