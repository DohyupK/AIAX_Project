# 전달사항 — 공정 최적화 실시간: 샷 수집 Flink job · mes 목업 삭제 요청 (JH → MS)

- 작성: JH, 2026-11-19
- 대상: MS (DB·Flink·`mes` 스키마)
- 함께 보는 문서: [2026-11-19_DH_공정실시간_배포_샷수집_요청.md](2026-11-19_DH_공정실시간_배포_샷수집_요청.md) (DH 쪽 배포·producer)
- 관련: PR #29, [DB연동_내역/2026-11-16_JH_process_optimization.md](../../DB연동_내역/2026-11-16_JH_process_optimization.md)

## 요약

공정 최적화 대시보드에 **실시간 따라가기**를 넣었습니다(날짜가 오늘이면 `mes.investment_casting` 의 새 샷을 5초마다 증분 조회). JH 는 **mes 원본만 읽기**(계정 `app_lake`)라 샷이 mes 에 들어오기만 하면 됩니다.
실제 샷을 넣는 경로(Kafka → Flink → mes)와, 그 전에 목업 정리를 부탁드립니다.

## 요청

| # | 요청 | 이유 |
|---|------|------|
| 1 | **샷 수집 Flink job** — 토픽(예: `aiax.shot.ingest`) → 형식 검사 → `mes.investment_casting` INSERT (계정 `app_mes`) | 이미지 수집 job [`MS/db/flink/jobs/image_ingest.py`](../../MS/db/flink/jobs/image_ingest.py) 와 같은 구조면 됨 (일시 오류 재시도 / 데이터 오류 로그 후 건너뜀) |
| 2 | **메시지 형식 확정** (아래 표) — DH producer 와 공유 | JH 화면이 아래 칼럼을 그대로 읽음 |
| 3 | **`casting_id` 생성 규칙·중복 처리** — 형식 `L<라인번호>_YYMMDD_HHMMSS_생산번호` (예: `L2_261101_000336_1`, 2026-11-19 MS 변경 반영) | 같은 메시지가 다시 와도 두 번 쌓이지 않게(UPSERT 또는 건너뜀). JH 실시간 API 의 `after` 값도 이 형식(`^L\d+_\d{6}_\d{6}_\d+$`)만 받음 |
| 4 | **전송 시작 직전 mes 목업 삭제** | 목업이 **11-30 까지** 미리 들어가 있음(오늘 이후 18,093샷). 남아 있으면 실데이터와 같은 날·시간대에 섞여 생산량·불량률이 두 배로 잡히고 `casting_id` 충돌 가능 |
| 5 | 삭제 시 **참조 테이블 정리** | `mes.investment_casting` 을 외래키로 참조: `mes.casting_image`, `ai.quality_prediction`, `ai.defect_label`, `ai.defect_discard`, `ai.quality_image_pool.matched_casting_id`, `lake.lake_investment_casting` |
| 6 | 삭제 시 **변경 기록 트리거 처리** | `trg_investment_casting_change_row` 가 삭제마다 `mes.investment_casting_change_log` 에 기록 → 약 13만 건. 잠시 끄거나 삭제 후 기록·워터마크 정리 (MS 판단) |
| 7 | (나중) **Spark lake 복제** | 불량 유형 라벨링·보호구 화면은 lake 사본을 읽어 복제가 돌아야 새 데이터가 보임. 공정 최적화·품질 검사·경영 리포트 생산은 mes 직접이라 영향 없음 |

## 메시지 형식 (제안 — `mes.investment_casting` 칼럼 그대로)

| 칼럼 | 형식 | JH 사용처 |
|------|------|-----------|
| `casting_id` | text, `L<라인번호>_YYMMDD_HHMMSS_생산번호` | 샷 고유키, 실시간 증분 커서 |
| `line_unit` | `line_no1` ~ `line_no3` | 라인 선택 |
| `production` | `CylinderHead` | (표시 고정값) |
| `timestamp` | date (생산일, KST) | 날짜 선택·「오늘」 판정 |
| `date` | time (하루 안 시각, KST) | 샷 시각·「현재 시각 이전」 조건·정렬 |
| `production_count` | integer | 샷 번호, 같은 시각일 때 정렬 |
| 공정 변수 17개 | double | 설비 장면 라벨·변수 모니터·관리도·1차(ML) 점수 입력 |
| `passorfail` | 0 / 1 (모르면 null) | 실제 판정 비교 |

공정 변수 17개: `mold_temperature`, `facility_cycletime`, `production_cycletime`, `mechanical_strength`, `molten_capacity`, `injection_pressure`, `sleeve_temperature`, `top_temp1`~`4`, `bottom_temp1`~`4`, `biscuit_thickness`, `cooling_water_temp`

- **주의**: JH 실시간 조건이 `"timestamp" = 오늘(KST) AND date <= 지금(KST)` (DB 서버 시계 `now() AT TIME ZONE 'Asia/Seoul'`) 이라, 생산일·시각을 **KST** 로 넣어 주세요. UTC 로 넣으면 9시간 어긋나 화면에 늦게 나타남.

## 진행 순서 (제안)

```
1. DH  PR #29 병합·배포
2. MS  샷 수집 Flink job + 메시지 형식 확정 (DH 와 공유)
3. DH  샷 producer / 시뮬레이터
4. MS  mes 목업 삭제 (5·6항)          ← 전송 직전
5. DH  전송 시작 (샷 → 이미지 순)
```

JH 코드는 이 과정에서 추가 변경 없음. 질문은 JH 로.
