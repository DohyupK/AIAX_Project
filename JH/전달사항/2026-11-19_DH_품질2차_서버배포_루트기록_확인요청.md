## 요약

품질 검사 대시보드 2차(DL) 검사 연결 완료 — `mes.casting_image` 샷 이미지를 TM `.onnx` 모델로 판정 (`GET /api/casting/second`). 서버에서 돌리려면 아래 준비가 필요하고, 실제 이미지 수집 계획 확인을 부탁드립니다.

## 요청

| # | 요청 | 이유 |
|---|------|------|
| 1 | **실제 샷 이미지 수집 계획** — 언제부터, 어느 라인·날짜 범위로 `mes.casting_image` 에 들어오는지 | 지금 이미지는 Flink 검증용 테스트 5건(11-30, `original_uri` = `mock-pc`)뿐 → 다른 샷은 화면에 전부 「이미지 없음」 |
| 2 | **이미지 해상도** — 지금 384×384 PNG. 실제 카메라·수집도 384 인지 | TM 평가는 512×512 원본 기준 (TM 에도 같은 질문 전달) |
| 3 | `ai.quality_image_pool`(랜덤 매칭) 을 **누가·언제 채우는지** | DB 설명상 매칭되면 `mes.casting_image` 로 들어감 — 화면 2차 대상 범위가 여기에 달림 |
| 4 | **서버 배포 시 JH API 준비** — `cd JH/api && uv sync` (새 패키지 onnxruntime 1.32.0 등), `git lfs pull` (모델 111MB `TM/model_dl/…_01.onnx`) | LFS 를 안 받으면 130바이트 포인터만 있어 2차 화면에 「Git LFS 포인터」 오류 표시. 서버 메모리: 모델 로드 시 약 0.3~0.5GB 추가 |
| 5 | (MS 쓰기 계정이 생기면) **서버 `.env` 에 비밀번호 반영** | 요청서: [2026-11-18_MS_모델레지스트리_쓰기계정_요청.md](2026-11-18_MS_모델레지스트리_쓰기계정_요청.md) |
