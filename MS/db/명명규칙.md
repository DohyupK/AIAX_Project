# DB 명명 규칙 (테이블·컬럼 이름 정하는 법)

담당: MS · 제정: 2026-11-06 · 적용 범위: `aiax` DB의 `lake`, `mart` 스키마와 이후 추가되는 모든 테이블

이 문서는 팀원 누구나 **같은 방식으로 이름을 짓고, 이름만 보고 뜻을 알 수 있게** 하기 위한 규칙입니다.
새 테이블·컬럼을 만들거나, 이 DB를 쓰는 코드를 짤 때 이 문서를 기준으로 합니다.

---

## 1. 한 줄 요약

> **원본 데이터의 컬럼은 원본 이름을 그대로 쓰고, 우리가 새로 만드는 테이블·컬럼은 영어 소문자 + 밑줄(snake_case)로 뜻이 보이게 짓는다. 모든 이름에는 한글 설명(COMMENT)을 단다.**

| 좋은 예 | 나쁜 예 | 이유 |
|---|---|---|
| `mold_temperature_avg_10` | `A_001`, `col7` | 코드형은 설명 없이 아무도 못 읽음 |
| `defect_rate` | `DefectRate`, `defect rate` | 대문자·띄어쓰기 금지 (새로 짓는 이름) |
| `is_outlier` | `flag`, `chk` | 값의 뜻이 이름에서 드러나야 함 |

## 2. 원본 이름 우선 원칙 (2026-11-06 결정)

원본 데이터(CSV·Kafka 메시지)에서 온 컬럼은 **원본 이름을 그대로** 씁니다. EDA·모델·추론 담당자가 가이드북과 CSV에서 보던 이름 그대로 DB를 쓸 수 있게 하기 위해서입니다.

| 경우 | 처리 |
|---|---|
| 원본 이름에 대문자가 있음 | 따옴표 없이 그대로 만든다 → PostgreSQL이 **자동으로 소문자**로 저장 (`PassOrFail` → `passorfail`). SQL에서는 어느 쪽으로 써도 동작 |
| 원본 이름이 SQL 단어와 겹침 (`timestamp`, `date`) | 그대로 쓴다. PostgreSQL에서는 컬럼 이름으로 사용 가능 (확인 완료). 다른 DB로 옮길 일이 생기면 재검토 |
| 원본 이름과 실제 뜻이 다름 (`mold_temperature` = 용융온도 등) | 이름은 그대로 두고, **한글 설명(COMMENT)에 실제 뜻**을 적는다 |
| 원본에 없는 값을 새로 만듦 (`casting_id` 등) | 이 문서 3절 이후의 규칙으로 이름을 짓는다 |

주의: pandas·Spark로 DB를 읽으면 컬럼 이름이 소문자(`passorfail`)로 나옵니다. CSV(`PassOrFail`)와 대소문자만 다릅니다.

## 2-1. 새로 짓는 이름에 이 방식을 쓰는 이유

| 방식 | 판단 |
|---|---|
| 코드형 (`TB_A001`, `A_001`) | 오래된 ERP·MES·PLC에서 쓰지만, 코드표 없이는 해석 불가. 새 팀원·AI 에이전트가 매번 사전을 찾아야 함 → **사용 안 함** |
| 표준 약어형 (`MOLD_TMP`, `INJ_PRS`) | 대기업 표준 사전 방식. 일관성은 좋지만 약어를 외워야 함 → **약어는 최소한만 허용** |
| 의미형 snake_case (`defect_rate`) | 바로 읽히고 팀 규칙(AGENTS.md 4항: 소문자 snake_case)과 일치 → **채택** |

어떤 방식이든 실무에서 중요한 것은 **이름의 뜻을 적어 두는 것**이므로, 의미형 이름 + 한글 설명(COMMENT)을 함께 씁니다.

## 3. 공통 규칙

1. **문자:** 영어 소문자 `a-z`, 숫자 `0-9`, 밑줄 `_`만 사용. 숫자로 시작 금지.
2. **길이:** 30자 이내 권장 (PostgreSQL 한계는 63자).
3. **언어:** 영어 단어만. 한글·로마자 표기(`ondo`) 금지. 한글 이름은 사전과 `COMMENT`에.
4. **예약어 금지 (새로 짓는 이름):** `date`, `time`, `timestamp`, `user`, `order`, `group`, `value`, `type`, `desc` 등은 단독으로 쓰지 않음 (`produced_date`, `defect_type`처럼 앞에 대상을 붙임). 원본에서 온 이름은 2절에 따라 예외.
5. **뜻과 일치 (새로 짓는 이름):** 이름만 보고 내용을 알 수 있게 짓는다. 원본 이름의 뜻이 다를 때는 2절대로 사전에 기록한다.
6. **애매한 이름 금지:** `data`, `info`, `value1`, `temp`(임시/온도 혼동), `etc`.
7. **단수형:** 테이블·컬럼 모두 단수 (`investment_casting`, `investment_castings` 아님).

## 4. 스키마 (고정)

| 스키마 | 용도 | 이름 규칙 적용 |
|---|---|---|
| `mes` | 원본 보관 | 원본 컬럼은 **원본 이름 그대로** (2절). 추가 컬럼과 테이블 이름은 이 규칙 적용 |
| `lake` | 정제 데이터 | 원본 컬럼은 mes와 같은 이름·순서. `lake.lake_investment_casting` = `casting_id`(mes 외래키) + 20개 컬럼 (2026-11-07, MS 지정 이름) |
| `mart` | 학습·분석용 | **이 규칙 적용**. `mart.mart_investment_casting` = `casting_id`(lake 외래키) + 18개 컬럼 (2026-11-07, MS 지정 이름). `passorfail` 빈 값 금지 |

새 스키마는 만들지 않는 것을 원칙으로 하고, 필요하면 MS와 협의합니다.

## 5. 테이블 이름

형식: **`{도메인}_{대상}[_{용도}]`**

| 부분 | 규칙 | 예 |
|---|---|---|
| 도메인 (접두어) | 데이터 출처·분야. 공통 기준정보는 생략 | 원본 파일에서 온 테이블은 파일 이름 그대로(`investment_casting`), 그 외 `img_` 이미지(예정) |
| 대상 | 한 행이 무엇인지를 나타내는 명사 | `shot`(제품 1개 생산), `equipment`, `lot` |
| 용도 (접미어, 필요할 때만) | 아래 표에서 선택 | `_feature`, `_daily` |

| 접미어 | 뜻 | 예 |
|---|---|---|
| (없음) | 대상 1개 = 1행인 기본 테이블 | `mes.investment_casting` |
| `_feature` | AI 학습용 특징값 표 | `mart.investment_casting_feature` (예시) |
| `_label` | 정답(품질 결과) 표 | `mart.investment_casting_label` (예시) |
| `_hourly`, `_daily` | 시간·일 단위 요약 | `mart.investment_casting_daily` (예시) |
| `_range` | 관리 범위·기준값 | `mart.investment_casting_range` (예시) |
| `_run`, `_batch` | 실행·적재 이력 | (예시) `ingestion_batch` |
| `_map` | 두 대상의 연결 | `mart.img_shot_map` (이미지 ↔ 제품, 예정) |

- `tb_`, `t_` 같은 접두어는 붙이지 않습니다 (스키마가 이미 구분해 줌).
- 원본·정제·집계 단계는 테이블 이름이 아니라 **스키마**로 구분합니다 (`mes`/`lake`/`mart`). 같은 대상은 스키마가 달라도 같은 이름을 씁니다.

## 6. 컬럼 이름

### 6-1. 형식별 규칙

| 종류 | 규칙 | 예 |
|---|---|---|
| 기본키 | `{대상}_id` | `casting_id`, `equipment_id` |
| 외래키 | 참조하는 기본키와 **같은 이름** | `equipment_id` |
| 일시 (`timestamptz`) | `{사건}_at` (과거분사) | `produced_at`, `ingested_at`, `created_at` |
| 날짜 (`date`) | `{사건}_date` | `produced_date` |
| 시간 길이 | `{대상}_sec` (초) | `cycle_sec` (단위 확인 후) |
| 참/거짓 | `is_` / `has_` + 형용사·명사 | `is_outlier`, `has_missing` |
| 개수 | `{대상}_cnt` | `shot_cnt`, `defect_cnt` |
| 비율 | `{대상}_rate` (0~1) | `defect_rate` |
| 번호(순번) | `{대상}_no` | `run_no` |
| 코드값 | `{대상}_code` | `defect_code` |
| 이름(글자) | `{대상}_name` | `pipeline_name` |
| 같은 종류 여러 개 | 끝에 `_1`, `_2` … | `camera_1` ~ `_4` (원본 `top_temp1`처럼 원본에서 온 이름은 원본 그대로) |

### 6-2. 단위

- 단위가 **확인된 경우에만** 끝에 붙입니다: `_c`(℃), `_sec`(초), `_mm`, `_bar`, `_pct`(%).
- 단위가 확인되지 않으면 붙이지 않고, 사전의 단위 칸에 `미확인`이라고 적습니다. 나중에 확인되면 이름은 그대로 두고 사전만 갱신합니다.

### 6-3. 통계·파생 컬럼 (`mart`)

형식: **`{원래 컬럼}_{통계}[_{범위}]`**

| 통계 접미어 | 뜻 | 예 |
|---|---|---|
| `_avg`, `_min`, `_max`, `_std` | 평균, 최소, 최대, 표준편차 | `mold_temperature_avg` |
| `_diff` | 직전 대비 변화량 | `mold_temperature_diff` |
| 범위 `_10`, `_1h` | 최근 10개 / 최근 1시간 기준 | `mold_temperature_avg_10` (직전 10샷 평균) |

### 6-4. 허용 약어 (이것 외에는 단어를 줄이지 않음)

| 약어 | 원래 단어 | 약어 | 원래 단어 |
|---|---|---|---|
| `id` | identifier | `cnt` | count |
| `no` | number (순번) | `sec` | second |
| `temp` | temperature | `pct` | percent |
| `avg` / `min` / `max` / `std` | 통계 | `diff` | difference |
| `qty` | quantity | `img` | image |

`pressure`, `thickness`, `injection`처럼 위 표에 없는 단어는 줄이지 않습니다 (`prs`, `thk`, `inj` 금지).

## 7. 한글 설명 (필수)

모든 테이블·컬럼에 `COMMENT`로 한글 이름·원본 이름·단위·설명을 적습니다 (`init/07_comments.sql`). DBeaver 등에서 바로 보입니다.

```sql
COMMENT ON COLUMN mes.investment_casting.mold_temperature IS '용융온도 (원본: mold_temperature) — 이름은 금형 온도지만 실제는 쇳물 온도 (단위 미확인)';
```

별도 사전 테이블은 두지 않습니다 (2026-11-06 삭제). 컬럼이 많아져 검색·관리가 필요해지면 다시 검토합니다.

## 8. 주조 데이터셋 컬럼 (`mes.investment_casting`, 2026-11-07 적용)

원본 23개 컬럼은 **원본 이름 그대로**(대문자는 소문자로 저장), 원본에 없는 컬럼은 맨 앞의 `casting_id`(원본 값으로 자동 생성하는 행 식별자) 하나뿐입니다. 테이블 이름은 원본 파일 이름(`Investment_Casting.csv`)을 소문자로 씁니다. 계산값(`produced_at` 등)은 mes에 두지 않고 lake에서 만듭니다.

|---|---|---|---|---|

| `production_count` | `production_count` | 생산 번호 | integer | |

## 9. 이름을 새로 만들거나 바꿀 때

1. 이 문서의 규칙으로 이름을 정합니다. 애매하면 MS에게 문의합니다.
2. `init/07_comments.sql`에 한글 설명(`COMMENT`)을 먼저 적습니다.
3. 이미 쓰고 있는 이름을 바꿀 때는 그 테이블을 쓰는 기능 담당자에게 알리고, `DB연동_내역`의 해당 기록도 갱신합니다.
4. 이 문서의 8절(표준 이름 표)도 함께 갱신합니다.
