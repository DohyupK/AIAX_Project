서버 DB `aiax`의 org 스키마가 새 구조로 바뀌었습니다 (2026-11-17 적용).
- 구조·규칙: `01 DB 설명서.md`
- 실제 값: 서버 DB `aiax`의 org (테이블 29개). CSV는 깃에 올리지 않고 압축 파일로 따로 전달. 다시 만들 때는 `MS/db/init/09`, `10`
- 아래 표는 기존 코드가 바뀐 DB에 맞추려면 고쳐야 할 곳입니다. AI에게 이 파일·설명서·CSV를 같이 보여 주고 작업하면 됩니다.

## 이름이 바뀐 것 한눈에

| 기존 | 새 |
|---|---|
| `vender_company`, `vender_worker`, `vender_gate_log`, `vender_*` 컬럼 | `vendor_*` |
| 사번 `E10001` | `e0001` ~ `e0054` (부서와 무관한 일련번호, 소장 e0001) |
| 사원증 `EMPE10001` | `ec0001` ~ |
| 하청 카드 `hb260601a` | `vc0001` ~ (끝 글자 a/b 없음, 게이트는 `gate_card`) |
| 하청업체 `HB260601` | `v0001`, `v0002` |
| `dept_code` '10'~'70' (text) | 1000 ~ 7000 (integer) |
| `team_code` 'casting1' (text) | 10 ~ 60 (integer), 이름은 `team_name` |
| `position_code` 100 ~ 700 | 10000 ~ 70000 |
| `employee_info.age` | 삭제 → `birth_date` (나이는 조회 때 계산) |
| `commute_type` | `in_out` |
| 페이지 권한 6개 (`dept_code`, `position_name`, `page_feature`) | 9개, `access_code` + `access_level`(read/edit) |
| `late` 등 "1"/빈칸 | boolean |
| `employee_record.employee_card_id` | `employee_no` |

# 팀원 전달 사항 (DB가 바뀌어서 앱에서 바꾸면 좋을 것)

DB 반영 후 해당 팀원에게 넘길 내용. 팀원이 AI에게 그대로 보여주고 작업할 수 있게 "바뀐 것 → 이렇게 바꾸면 됨"으로 적음.

| # | 받는 사람 | 바뀐 DB | 지금 연결된 곳 | 이렇게 바꾸면 됨 |
|---|---|---|---|---|
| 1 | 팀장님 | `team_code` 의미 변경 (이름 → 번호 10~60), 이름은 `team_name` | team을 쓰는 코드 | 팀 이름은 `team_name`, 번호는 `team_code`(정수)로 조회 |
| 2 | 팀장님 | 접근 코드 5자리 규칙, 소장 71100 | 접근 코드 계산 함수 | 계산 함수 제거. 값은 `access_code` 테이블에서 조회 (DB 트리거가 자동 계산) |
| 3 | DH | `vender` → `vendor` (테이블·컬럼 이름 전부) | `DH/api/common/org_permission_logic.py` | 쿼리의 `vender_*` 이름을 `vendor_*`로 변경 |
| 4 | JH | employee_info `age` 삭제, `birth_date` 추가 | `JH/api/hr/router.py`(조회·입력), `rules.py`(15~100 검사) | 입력은 `birth_date`, 나이는 조회할 때 생년월일로 계산 |
| 5 | JH | access_code·dept_roster·team_roster를 DB 트리거가 자동으로 맞춤 | `JH/api/hr/router.py` `_sync_rosters()`, `rules.access_code_of()`(옛 공식) | employee만 바꾸면 됨. 명단·접근 코드를 직접 넣는 코드 제거 |
| 6 | DH | 하청 카드 번호가 vc0001~로 바뀌어 끝 글자(a/b)가 없음. vendor_worker `gate` 삭제 | `DH/api/common/org_permission_logic.py` `gate_flags_for_vender_card()` (카드 끝 글자로 게이트 판단) | 게이트는 gate_card의 `gate_a`/`gate_b`에서 조회 |
