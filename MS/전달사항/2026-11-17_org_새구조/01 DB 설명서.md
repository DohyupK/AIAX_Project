## 접근 코드 (`org.access_code`)

페이지 열람·수정 권한은 **접근 코드가 일치하는지**로 구분합니다. 숫자의 크기로 비교하지 않습니다.

### 5자리 규칙

| 자리 | 의미 | 값 |
|---|---|---|
| 1 (만) | 직급 | `position_code` |
| 2 (천) | 부서 | `dept_code` |
| 3 (백) | 부서장 여부 | 부서장 100, 아니면 0 |
| 4 (십) | 팀 | `team_code` (팀 없음 0) |
| 5 (일) | 팀장 여부 | 팀장 1, 아니면 0 |

**접근 코드 = position_code + dept_code + (부서장 100) + team_code + (팀장 1)**

- 모든 사원이 같은 공식으로 계산합니다. 예외 없음.
- 소장(1명)은 경영부 소속 경영부 부서장이고 팀이 없습니다.
- 부서·팀은 각각 한 자리라 9개까지 표현됩니다.

### 코드 값

| 직급 | position_code | | 부서 | dept_code | | 팀 | team_code |
|---|---|---|---|---|---|---|---|
| 인턴 | 10000 | | 경영부 | 1000 | | (없음) | 0 |
| 사원 | 20000 | | 설비부 | 2000 | | casting1 | 10 |
| 대리 | 30000 | | 생산부 | 3000 | | casting2 | 20 |
| 과장 | 40000 | | 시스템개발부 | 4000 | | casting3 | 30 |
| 차장 | 50000 | | 안전부 | 5000 | | maintenance | 40 |
| 부장 | 60000 | | 품질부 | 6000 | | cost | 50 |
| 소장 | 70000 | | R&D부 | 7000 | | tf | 60 |

### 예시

| 사람 | 계산 | 접근 코드 |
|---|---|---|
| 생산부 부서장이면서 casting2 팀장인 차장 | 50000 + 3000 + 100 + 20 + 1 | **53121** |
| 생산부 casting2 인턴 | 10000 + 3000 + 0 + 20 + 0 | **13020** |
| 소장 (경영부 부서장, 팀 없음) | 70000 + 1000 + 100 + 0 + 0 | **71100** |

### 자동 갱신

- 직급·부서·팀이 바뀌거나 부서장·팀장이 바뀌면 DB 트리거가 해당 사원의 접근 코드를 자동으로 다시 계산합니다.
- 같은 접근 코드를 여러 사원이 가질 수 있습니다.

## 페이지 권한

페이지마다 권한 테이블이 있고, **접근 코드당 1행**입니다.

| 행 | 뜻 |
|---|---|
| 없음 | 페이지에 들어올 수 없음 |
| `read` | 페이지 보기만 |
| `edit` | 보기 + 수정 버튼 (어떤 버튼이 수정 버튼인지는 화면에서 정함) |

### 권한을 정하는 방법

1. 설명서의 기준(부서·직급·직책)은 사람이 읽기 위한 규칙입니다.
2. DB에는 이 규칙을 **실제 사원이 가진 접근 코드 하나하나에 적용한 결과**가 행으로 들어갑니다.
3. 규칙은 접근 코드의 자리로 판단합니다.

| 판단 | 접근 코드 자리 | 예 |
|---|---|---|
| 직급 | 만의 자리 (1 인턴 ~ 7 소장) | 4xxxx = 과장 |
| 부서 | 천의 자리 (1 경영 ~ 7 R&D) | x3xxx = 생산부 |
| 부서장 | 백의 자리 1 | xx1xx |
| 팀 | 십의 자리 (0 없음, 1~6) | xxx2x = casting2 |
| 팀장 | 일의 자리 1 | xxxx1 |

### 적용 순서

위에서부터 처음 맞는 규칙 하나만 적용합니다.

1. **소장** (만의 자리 7) → 모든 페이지 `edit`
2. 페이지별 **edit 기준**에 맞으면 → `edit`. 단, **인턴**(만의 자리 1)은 `read`로 내림
3. 페이지별 **read 기준**에 맞으면 → `read`
4. **부서장**(백의 자리 1) 또는 **시스템개발부**(천의 자리 4) → `read`. 인사 관리는 제외
5. 어디에도 안 맞으면 → 행 없음 (접근 불가)

### 페이지별 기준

| 페이지 | 권한 테이블 | read | edit |
|---|---|---|---|
| 메인 | `main_page` | 전 사원 | 부서장, 팀장 |
| 공정 최적화 | `process_optimization_page` | 생산부, 설비부, 품질부, R&D부 | 생산부·설비부 과장 이상 |
| 품질 검사 | `quality_inspection_page` | 품질부, 생산부, 설비부, R&D부 | 품질부 대리 이상 |
| 불량 유형 라벨링 | `defect_labeling_page` | 생산부, R&D부 | 품질부 전원 |
| 작업자 안전 관리 | `worker_safety_page` | 생산부, 설비부, 팀장 전원 | 안전부 전원 |
| 인사 관리 | `hr_management_page` | 경영부 대리 이상 | 경영부 과장 이상 |
| 경영 관리자 리포트 | `management_report_page` | 팀장 전원, 경영부 전원 | 경영부 과장 이상 |
| Model Management | `model_management_page` | 품질부, R&D부 | R&D부 대리 이상, 시스템개발부 과장 이상 |
| 사내 문서함 | `company_documents_page` | 전 사원 | 대리 이상 |

(부서장·시스템개발부의 `read`는 적용 순서 4번으로 모든 페이지에 들어가므로 표에 따로 적지 않습니다.)

### 기준 이유

| 규칙 | 이유 |
|---|---|
| 소장 전 페이지 edit | 회사 최고 책임자 |
| 부서장 전 페이지 read | 다른 부서와 협업하고 결과를 확인해야 함. 수정은 담당 부서에 맡김 |
| 시스템개발부 전 페이지 read | 시스템 전체를 관리·점검함 |
| 인사 관리는 위 둘에서 제외 | 개인정보라 인사 담당(경영부)만 봄 |
| 인턴 edit 불가 | 실무 수정 권한 없이 보기만 함 |
| 메인 | 공지·일정을 보는 첫 화면이라 모두 봄. 등록은 조직을 이끄는 부서장·팀장 |
| 공정 최적화 | 공정 관련 부서와 R&D가 봄. 공정 값 변경은 생산에 영향이 있어 현장 책임자(생산·설비 과장 이상)만 |
| 품질 검사 | 공정 관련 부서가 결과를 봄. 판정 수정은 품질 실무자(대리 이상) |
| 불량 유형 라벨링 | 라벨링은 품질 실무 작업. 생산부는 결과 확인, R&D부는 모델 학습 데이터로 봄 |
| 작업자 안전 관리 | 현장 부서와 팀원을 챙기는 팀장이 봄. 관리는 안전부 |
| 경영 관리자 리포트 | 의사결정용이라 팀장 이상과 경영부가 봄. 작성은 경영부 과장 이상 |
| Model Management | 모델은 R&D, 배포는 시스템개발부가 담당. 품질부는 모델 성능 확인 |
| 사내 문서함 | 모두 봄. 문서 업로드는 대리 이상 |

## 근무 기준

| 구분 | 대상 | 근무 시간 | 기준 시간 |
|---|---|---|---|
| 3조 3교대 | casting1·2·3 (팀 = 조) | 주간 06~14 / 오후 14~22 / 야간 22~06. 팀마다 1주 단위로 돌아감 | 8시간 |
| 정시 | 그 외 사원 (cost, maintenance, tf, 소장) | 09~18 (점심 1시간 포함) | 9시간 |

### 근무 기록(`employee_record`) 판정

| 컬럼 | 판정 |
|---|---|
| `late` | 그날 첫 IN이 근무 시작 시각 이후 |
| `early_leave` | 그날 마지막 OUT이 근무 끝 시각 이전 |
| `absent` | 그날 IN 기록 없음. 결근 1일 = 연차 1일 차감 |
| `work_deficit` | 출근했지만 실제 근무시간이 기준 시간 미만 |
| `overtime_hour` | 근무 끝 시각 이후 일한 시간. 30분 이상일 때만 기록 (아니면 빈칸) |

- 야간조처럼 자정을 넘기면 `work_date`는 근무를 시작한 날짜입니다.
- 출입 게이트 a·b는 회사 정문이고, 게이트 출입 로그로 출근 기록이 만들어집니다.
- 사원증의 `attendance_status`는 **지금 회사 안(present)/밖(absent)**입니다. 출입 로그 IN이면 present, OUT이면 absent로 바로 바뀝니다. 오늘 출근했는지는 `attendance`에 오늘 날짜 행이 있는지로 봅니다.
